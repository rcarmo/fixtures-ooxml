# OOXML fixture acquisition

The v0.43.0 [retirement ledger](../ledgers/observed-generated-retirement.json) preserves the 35 observed Go-generated byte identities. The committed S and P variants remain separate inputs. Their names do not establish producer identity or feature coverage; select an archive for its scenario predicate and valid package graph. The removed G workbooks all have dangling workbook relationships and a calculation-chain entry for C5 without a matching formula.

## Required presentation inputs

1. **Two slide masters.** Create a PowerPoint presentation with distinguishable master names or themes, at least one layout for each master, and slides using both. Preserve the untouched application export and record version, platform, size and SHA-256. Check that `ppt/slideMasters/slideMaster1.xml` and `slideMaster2.xml` exist, that `p:sldMasterId` has two entries, and that slide → layout → master links resolve. All three existing `multiple-masters` variants have only one slide master; the G variant's second master is a *notes* master. The existing variants can serve truthful one-slide-master scenarios, not a two-slide-master positive.
2. **Hidden slide and visible control.** In PowerPoint, hide slide 3 of a four-slide presentation, save and reopen the original, and confirm the identity and visible state of all four slides. Preserve the original with producer/version/platform/hash. The current P `hidden-slides` fixture is fully visible and remains a control. S uses namespaced `show="0"` on slide 3; verify its interpretation in PowerPoint before using it as an application-confirmed positive. The retired G file's unqualified `show="false"` has unestablished generator provenance.

## Conditional spreadsheet input

3. **Calculation chain.** Acquire an untouched Excel-authored workbook with a formula cell named by a real `xl/calcChain.xml` entry only if chain intake or preservation is required. Validate workbook relationships, content types, chain target, referenced formula, and application version. If current Excel does not emit a chain, find an older untouched workbook with custody or leave the behaviour unsupported. The deterministic Go-produced `owned-order.xlsx` candidate has a valid OPC graph for internal tests but is not an independently Excel-authored input.

## Optional producer checks

4. **Excel-authored baselines.** Where independent producer diversity is required, obtain separate application originals for data types, single cell, conditional formatting, minimal sheet, defined names, formatting, formula caches, merges, tables and multiple sheets. These ten existing S/P pairs generally identify Openpyxl 3.1.5. The P threaded-comment workbook identifies Excel 16.0300 and is an application-marked candidate, not independently proven Office custody.
5. **Word/PowerPoint originals.** If strict authorship proof is required, preserve untouched application exports or compare independent Office-open/save outputs and a renderer/viewer result for style inheritance, notes themes, table height and hidden-slide state. Application metadata inside a ZIP alone cannot prove its author.

Register new originals with intact bytes, provenance and hashes. A new manifest entry alone does not earn execution credit: bind and run the exact scenario outcomes in each consumer separately.
