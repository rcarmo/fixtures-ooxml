# Slide visibility inputs

The [slide-visibility workflows](../workflows/pptx/slide-visibility.feature) distinguish a retained package observation from an application-confirmed PowerPoint positive. They do not infer producer identity from application metadata.

The committed `hidden-slides-e01ded1106a2.pptx` archive has four slides. Its `ppt/slides/slide3.xml` root carries **namespaced** `p:show="0"`; the other slide roots have no `show` attribute. The separate four-slide `hidden-slides-fa245a3df00f.pptx` archive has no slide-root `show` attributes. ECMA-376 Part 1 (fifth edition, 2016), Annex A, `CT_Slide`, defines an **unqualified** `show` attribute with a default of `true` when absent. The namespaced marker does not satisfy that schema attribute. The retained-input case checks the exact marker, its absence elsewhere, slide relationship and part identity, and unchanged input bytes. It does not count either input as an application-confirmed hidden positive.

PowerPoint has not independently confirmed the retained S file's hidden state. The Office-positive scenario requires an untouched four-slide PowerPoint export with only slide 3 hidden, reopened in PowerPoint and registered with original bytes, version and platform. See the [acquisition list](../docs/fixture-acquisition.md). No current `multiple-masters` fixture has two slide masters, so it cannot support a two-slide-master positive.

Go's reader reports slide 3 hidden for S; Python's hidden-slide tool reports zero hidden slides for the same input. These are reader observations, not PowerPoint confirmation. Bun's [native package test](../ledgers/consumers/bun-pptx-slide-visibility.json) independently inspects ordered slide relationships, namespace-qualified attributes and unchanged retained bytes with corruption controls; it has no canonical acceptance binding. Go's historical `hidden_slides.pptx` round-trip creates a new hidden slide and checks only that *some* slide is hidden after reopen; it cannot prove the pre-existing slide 3 identity. The Python hide/list tests check success or response shape without matching the retained slides. The [Go mapping](../ledgers/consumers/pptx-slide-visibility.json) and [Python mapping](../ledgers/consumers/python-pptx-slide-visibility.json) record those separate gaps. No consumer has execution credit for either case.
